# Future official protocol — proposal, not enabled

The user wants an experiment about what the simulation can do, without assuming a sale or revenue model. Local scientific/engineering work continues. Any future public token use must be assessed on its actual terms, not automatically classified as commercial merely from this prototype.

1. Choose the model/dataset and validate the specific circuit. Keep a public engineering/calibration ledger separate from official runs. Do not change output neurons or thresholds after observing the official seed/result. Document unsuccessful development attempts too.
2. Predefine the intervention controls and statistical criterion for the rule on development seeds. Freeze a holdout experiment before requesting new randomness. A sugar stimulus deliberately activating a feeding circuit demonstrates causal transduction, not financial judgment or spontaneous desire.
3. Fix one official manifest and budget; get explicit operator authorization **before** the official run starts. No discretionary approval after LAUNCH_SIGNAL if the experiment is to be described as autonomous under those terms. If a downstream safety invariant fails, stop and record the failure without quietly rerunning.
4. Proposed external commitment: publish canonical manifest bytes and hash to an independently retrievable append-only/time-anchored surface. Verify retrieval and temporal ordering. A Git timestamp, local file, IPFS content hash or unverified gist alone is not adequate proof of publication time.
5. Proposed randomness: specify a verifiable public beacon's exact network/chain hash, signature scheme, public key and a future round in the precommitment. Seed = first 32 bits, big-endian, of SHA-256(`bellfly-seed-v1` || manifest_hash_bytes || verified_round_randomness_bytes). Select the round before publishing the commitment; no choosing among future values. If unavailable/late/invalid, INVALID with no fallback seed. Pin verification library and archive the beacon response/signature. **No beacon integration has been executed in this MVP.**
6. A manifest should commit to the seed *mechanism*, not an already selected public outcome. Seed resolution belongs in its own linked execution record. Current local examples explicitly use FIXED_LOCAL and do not claim this procedure.
7. Run once; signed private runner evidence, a single authorized submission, provider reconciliation and independent RPC receipt/configuration validation. Archive all negative/error outcomes with the same visibility as positives.
8. Publish manifest, randomness proof, runner environment/code, spikes, decoder decision, submission and verified receipt. Clearly distinguish token contract, curve contract and pool identifier. Do not advertise a predicted/simulated address as a issued token.

Replay: first prove exact local matching, then specify cross-environment tolerances **before** comparison. If another environment changes the verdict, the official experiment is not adequately reproducible. Auditability alone is not trustless execution.
